The test runs `scripts/schedule_region.py` as a subprocess and asserts
`"KeyError" in proc.stderr`. That holds only where `GITHUB_EVENT_NAME` is unset.
Locally the script dies on the missing variable and the test passes (538 pass).
In Actions the variable is set, so the script proceeds and raises
`ValueError: unknown schedule` instead, and the assertion fails. The gate runs
before the scrape, so no scrape has started since the commit landed.

- Six failed runs were opened (43603186302, 43598793125, 43526860868,

  stopped at the offline test gate. The error text was read in one of them.

  It was an hourly Opolskie eligibility no-op with every scrape step skipped.
  That the other green runs since November 4 are also no-ops is an inference
  from the unchanged data branches, not something checked run by run.
- Roughly 40% of `Update listings` runs since November 4 are red.
- The live site's displayed freshness was not inspected.
